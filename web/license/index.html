How to attribute

Credit each module you use and cite its own URI. The general form is:

“FOMO <module> ontology, © FlandersMake@UGent – ISyE, Ghent University, licensed under CC BY 4.0. https://w3id.org/fomo/<module>”

Each module’s specification and its ontology (.ttl) file contain the exact attribution text for that module. Copy it from there when you can.

Scope, naming, and extensions

This license covers the ontology artifacts and their documentation. It does not cover the MKS software stack (triplestore, tooling, mapping pipelines), which has its own terms.

“FOMO”, “Federated Open Manufacturing Ontologies”, and “MKS” are names of Ghent University. CC BY 4.0 gives you no right to use these names or the related logos beyond what reasonable attribution requires, and no use may imply endorsement. If you redistribute or modify a copy, mark it clearly as changed and don’t present it as the official FOMO.

Every canonical module lives under the https://w3id.org/fomo namespace, at its own URI (https://w3id.org/fomo/<module>). Don’t edit the published ontologies to extend them. Create a new ontology in your own namespace instead, and pull in the FOMO modules you need with owl:imports (see the extension policy below).

Extension policy

You extend FOMO by referencing it, not by modifying it. That way anyone can build on the ontologies while the canonical versions stay stable and authoritative.

Rules

  1. Don’t modify the published ontologies in place. Only FlandersMake@UGent – ISyE maintains the files under the https://w3id.org/fomo/… module namespaces, and a FOMO IRI always resolves to the official, versioned definition.
  2. Extend by creating your own ontology. An extension must:
    • live in its own namespace, outside every https://w3id.org/fomo/<module># namespace;
    • import the FOMO modules it builds on with owl:imports, e.g. 
      <https://example.org/my-extension>
    a owl:Ontology ;
    owl:imports <https://w3id.org/fomo/manufacturing> .
    • add new classes and properties under your own namespace, and relate them to FOMO terms with rdfs:subClassOf, rdfs:subPropertyOf, owl:equivalentClass, skos:broader and similar properties.
  3. Never mint or redefine terms in a w3id.org/fomo module namespace (e.g. https://w3id.org/fomo/manufacturing#) that you don’t control. That is namespace squatting, and it isn’t allowed.
  4. Pin a version if you need reproducible results, by importing a version IRI such as owl:imports <https://w3id.org/fomo/manufacturing/0.2.0>.
  5. Attribute. Any use or extension must credit FOMO as the license above describes. Mark modified copies as changed, and don’t present them as the official FOMO or suggest that FlandersMake@UGent – ISyE endorses them.

Contributing to FOMO itself

Found a problem in a canonical ontology, or want to propose a change? Email arno.claeys@ugent.be.

Why this model

Only the maintainers control what resolves under w3id.org/fomo, so nobody else can change the official ontologies. An extension that imports FOMO instead of forking it stays compatible with other FOMO-based data and tools, and its version IRI records which release it was built against.
